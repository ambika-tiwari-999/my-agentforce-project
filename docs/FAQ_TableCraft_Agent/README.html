FAQ Subagent: Data 360 Connection, Prompt Templates, and Pipeline Comparison

This document describes in basic, direct terms how the current FAQ subagent (dining_info + FAQ (CHANGE #1) in TableCraft_Agent_1.agent) connects to Data 360, what prompt templates it uses, and how it compares to the standalone FAQ pipeline documented in ../ambika-monday-demo-faq-pipeline.md.

1. How the FAQ Subagent Currently Connects to Data 360

In the merged agent (TableCraft_Agent_1.agent), the FAQ subagent is named dining_info + FAQ (CHANGE #1). + CHANGE #1 DESCRIPTION: Its role is to answer restaurant-specific questions on menu, parking, hours, and other FAQs, grounding its answers in specific documents; if it cannot answer the question, it asks the user if they would like to call a number and provides the restaurant's phone number, taking no actions. It does not query Data 360 directly from Agent Script or Apex. Instead, the Data 360 connection happens inside the Prompt Builder template when the subagent calls the Answer_TableCraft_FAQ action.

Step-by-step connection path

  1. Subagent calls the Prompt Action:
    1. CHANGE #1 CHANGE #2 CHANGE #4
    • Inside subagent dining_info + subagent FAQ (CHANGE #1), the planner calls the action Answer_TableCraft_FAQ.
    • Answer_TableCraft_FAQ targets generatePromptResponse://Ambika_TableCraft_FAQ_Prompt and passes three inputs from the agent session:
      • Input:question (the diner's question from the chat transcript)
      • Input:restaurant_id (@variables.restaurant_id, e.g., REST-ATX-01)
      • Input:escalation_phone_number (@variables.escalation_phone_number, loaded from CRM Restaurant__c.Phone_Number__c)
      • + CHANGE #2 ADDITION: Input:operating_hours (@variables.operating_hours, loaded from CRM Restaurant__c.Operating_Hours__c so the single prompt has both CRM hours and phone number alongside Data 360 RAG)
      • + CHANGE #4 ADDITION: Input:current_date_time (the current date/time passed into the prompt so it can answer relative time questions such as "today", "tonight", or "right now")

    CHANGE #5 Why we are removing the Prompt Builder template and moving reasoning into the .agent file

    + CHANGE #5 ARCHITECTURE: In Salesforce Prompt Builder, <templateDataProviders> runs RAG automatically on every invocation and forces a second LLM call (DefaultGPT5Mini) inside the prompt template just to invoke RAG. We do not need Prompt Builder at all because the FAQ subagent can decide when it needs RAG and hold all guardrails directly in the .agent file:

    • 1. Pure code loads CRM context first (before_reasoning): Apex (validate_restaurant_context) deterministically loads operating_hours, escalation_phone_number, and current_date_time from CRM into @variables on the FAQ subagent (0 LLM calls).
    • 2. All guardrails live in subagent FAQ (reasoning.instructions): All tone, brevity, allergen, and refusal guardrails currently inside Ambika_TableCraft_FAQ_Prompt move into the .agent file under subagent FAQ. This keeps guardrails in one single place and removes the extra Prompt Builder LLM call.
    • 3. Subagent only calls RAG (via Apex) when it needs more info:
      • If the diner asks about hours or phone number, subagent FAQ already has those values in @variables and answers immediately using its guardrails (0 RAG calls, 0 Prompt Builder LLM calls).
      • If the diner asks about menu, parking, policies, dress code, or dietary options, subagent FAQ invokes an Apex action that calls the Data 360 retriever (scoped by restaurant_id) and returns the raw chunks to the subagent to answer.
