Appendix

Design decision
Core concept
Why we chose this
What we sacrifice
01Web access first
Deployment methodMIAW on OpenTable restaurant profile pages.
Meets diners where research and booking happen. Supports a controlled 10% → 50% → 100% rollout.
No mobile app or voice until web proves FCR, conversion, security, and consumption.
02Signed-in convenience + guest verification
Security & identitySigned in: MIAW supplies identity automatically. Signed out: first name + last name + email to book; reservation ID + email to modify or cancel.
Signed-in diners can immediately access their contact and prior reservations. Signed-out diners can still book or manage a reservation with minimum verification.
Two identity paths add validation, fraud-prevention, and recovery complexity. Every write still requires explicit confirmation.
03OpenTable API for CRUD
Transactional integrationApex → MuleSoft Omni-Gateway → OpenTable API.
Keeps OpenTable as the reservation system of record with real-time availability and status.
API authentication, rate limits, latency, and uptime become production dependencies.
04Knowledge Articles for RAG
Knowledge groundingSalesforce Knowledge indexed in Data 360 by restaurant and category.
Native governance, chunking, retrieval, citations, and permissions.
More work to connect 60,000 OpenTable profiles and keep content synchronized.
05OpenTable owns escalation
Human-in-the-loopOmni-Channel routes failures and exceptions to OpenTable support.
Restaurants inherit no agent-failure workload, reducing opt-in friction.
OpenTable assumes support capacity, training, routing, and SLA ownership.
06Flex Credits
Consumption modelAgentforce usage monitored in Digital Wallet.
Fits variable diner demand. Alerts at 75% and 90% create control points before traffic expands.
Variable spend requires active monitoring, forecasting, and optimization.

Slide 18

Design Decisions

Design decision
Why
01Web access first
Diners already research and book there, so web gives us the fastest adoption and the safest staged rollout.
02Signed-in convenience + guest verification
Members get immediate access while guests can still book and securely manage a reservation with minimal verification.
05TableCraft owns escalation
Agent failures and exceptions go to trained TableCraft support instead of adding work for restaurant staff.
06Flex Credits
Usage-based pricing fits variable diner demand and lets TableCraft monitor cost before each rollout expansion.
